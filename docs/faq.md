# 常见问题

## 为什么下载后没有 EXE？

请从[下载页](downloads.md)下载 `RuinsLootHelper-版本号-Windows-x64.zip` 并完整解压。GitHub 的“Code → Download ZIP”和“Source code”下载的是源码，里面没有打包好的 EXE。

## 游戏位置为什么还会重新连接？

安装路径会保存；游戏启动后角色和背包数据属于新的进程，仍需重新获取。助手不会复用上次游戏的旧内存地址。保存的安装路径失效时才重新查找位置。

## 为什么有的功能需要安装组件？

普通筛选通过读取游戏数据工作。原生自动拾取、锁定、回收和自动格子定位需要可选的游戏组件。它们默认关闭，主动安装后要重启游戏。0.3.4 已将组件放在完整包中，安装时无需连接 GitHub。

## 安装组件提示下载失败或证书错误？

更新到 0.3.4 或更新版本的完整包，完整解压并保留 `_internal` 文件夹，再点击“功能设置 → 原生功能 → 离线安装／更新游戏组件”。旧版首次联网下载的步骤已改为读取包内组件。

## 闪退怎么反馈？

记录助手版本、游戏版本、发生步骤，以及是否启用了原生组件。发行包附带“破晓助手一键诊断.bat”；源码中也在 `source/packaging/`。它生成本地诊断包，不会自动上传。分享前检查内容，不需要提供游戏存档或完整开发目录。

## 悬浮窗为什么不在全屏游戏上面？

真正的独占全屏可能盖住普通置顶窗口。使用游戏窗口模式，或自行启用助手提供的无边框选项。

## 是否自动更新？

0.3.4 会检查 GitHub 新版本并提醒，可点击下载。下载完成后按提示替换完整便携目录；助手不会直接覆盖正在运行的程序。检查更新需要联网，游戏组件的离线安装不受影响。0.3.0 等没有更新检测的旧版可直接从下载页升级。

## 免费下载等于任意授权使用源码吗？

许可范围以仓库的[许可说明](../NOTICE.md)和各第三方文件头为准。
